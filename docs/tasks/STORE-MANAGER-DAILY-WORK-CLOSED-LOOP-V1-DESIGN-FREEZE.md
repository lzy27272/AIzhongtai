# 店长每日工作闭环 V1 设计冻结

| 项目 | 冻结值 |
|---|---|
| 设计编号 | STORE-MANAGER-DAILY-CLOSED-LOOP-V1 |
| 业务岗位 | 店长/店总（岗位代码 `GENERAL_MANAGER`） |
| 冻结日期 | 2026-09-13 |
| 状态 | FROZEN / IMPLEMENTATION APPROVED |
| 首期范围 | 店长模板、日实例、提醒、证据、审核、日报汇总、受控智能分析 |

本文是店长每日工作闭环 V1 的业务和技术实施基线。集团总经理使用 `GROUP_GENERAL_MANAGER`，与本模板的门店店长 `GENERAL_MANAGER` 严格分离；区域经理继续冻结，不参与模板、提醒、审核或升级链。

## 1. 闭环目标

每天按门店本地时间自动生成店长应做事项，在事项开始前和临近截止时提醒本人；员工通过企业微信深链进入对应事项，填写结果并上传证据；证据满足模板规则后方可提交；主管审核后，事项及证据自动进入当日日报；系统只基于已落库事实生成摘要和风险提示。

```text
已发布模板 → 每日事项 → 定时提醒 → 填写/拍照/上传 → 证据校验
                                             ↓
日报事实 ← 审核通过 ← 主管审核 ← 提交记录 ←────────┘
   ↓
手工其他工作 + 事实摘要 + 风险提示
```

## 2. 店长日常模板 V1

### 2.1 仪容仪表与晨会

| 字段 | 冻结值 |
|---|---|
| 条目代码 | `GM_APPEARANCE_MORNING_MEETING` |
| 工作时间窗 | 08:30—09:00，门店时区，每个营业日 |
| 提醒 | 08:20 开始前提醒；08:50 截止前提醒；09:05 逾期提醒；09:15 主管升级提醒 |
| 填报内容 | 应到人数、实到人数、仪容仪表是否合格、晨会主题、任务分工、异常及整改 |
| 必传证据 | 至少 1 张现场拍摄照片；晨会记录文本必填；可追加 JPG/JPEG/PNG/PDF/DOCX/XLSX |
| 审核 | 主管人工审核；通过进入日报，退回后允许补充证据并再次提交 |

照片只证明提交设备在该时间上传了现场图，不做人脸识别、身份识别或考勤判定。

### 2.2 公共区域巡检

| 字段 | 冻结值 |
|---|---|
| 条目代码 | `GM_PUBLIC_AREA_INSPECTION` |
| 工作时间窗 | 10:00—11:00，门店时区，每个营业日 |
| 提醒 | 09:50 开始前提醒；10:50 截止前提醒；11:05 逾期提醒；11:15 主管升级提醒 |
| 检查点 | 大堂、设备间、库房 |
| 填报内容 | 每个检查点状态、发现问题、整改责任人、整改时限 |
| 必传证据 | 大堂、设备间、库房各至少 1 张现场拍摄照片；可追加 JPG/JPEG/PNG/PDF/DOCX/XLSX |
| 审核 | 主管人工审核；存在问题时必须填写整改责任人与时限 |

V1 不自动创建整改任务，避免错误派单；日报明确列出问题、责任人和时限。自动转整改任务作为 V1.1 变更项另行冻结。

## 3. 证据链冻结

- 移动端提供“现场拍照”和“选择文件”两个入口；现场拍照调用后置相机。
- 图片由服务端解码、清洗并写入可见水印，水印包含门店、服务端接收时间、事项及证据编号。客户端时间仅作参考，不作为可信完成时间。
- 每个附件保存原文件名、媒体类型、大小、原始摘要、清洗后摘要、采集方式、检查点、客户端拍摄时间、服务端接收时间和扫描状态。
- 允许格式固定为 JPG、JPEG、PNG、PDF、DOCX、XLSX；单文件不超过 20 MB，单项最多 10 个附件。
- 提交时服务端再次校验必传数量、采集方式和检查点，不能只依赖页面校验。
- 删除和下载均校验租户、组织范围、任职和记录所有权；审核完成的证据不得静默替换。

## 4. 状态与时间

```text
PLANNED → AVAILABLE → IN_PROGRESS → SUBMITTED → SATISFIED
                                   ↘           → FAILED → 补交
                    截止+宽限后 → MISSED ──────→ 补交
```

- `available_at`、`due_at` 由模板时间和门店 IANA 时区计算，数据库统一保存 UTC 时刻。
- 提醒采用幂等业务键，同一事项、同一提醒阶段只发送一次；发送失败进入既有投递重试队列。
- 09:00/11:00 是计划截止时间，5 分钟宽限结束后才标记 `MISSED`；逾期不关闭入口。
- 一人多岗位时按“任职 + 门店 + 条目 + 日期”分别生成，平台管理员身份本身不生成日常事项。

## 5. 日报组成

店长日报固定由三部分组成：

1. 日常工作事实：审核通过的晨会和巡检事项，显示完成时间、结论、异常及证据链接。
2. 其他工作：店长手工填报当天临时工作、经营决策和待跟进事项。
3. 智能分析：基于上述已保存事实生成完成率、逾期、异常、整改时限和次日关注建议，并保留来源引用。

未完成或未审核事项不得被表述为“已完成”；智能分析不得虚构人员、地点、结论或整改结果。首期在未配置外部模型时使用确定性规则摘要，并明确标记“规则分析”；后续接入模型仍须走既有 `ai_request`、来源和决策审计表。

## 6. 权限与主管链

- 店长仅处理本人有效 `GENERAL_MANAGER` 任职对应的事项。
- 主管从有效任职关系解析；没有主管时，事项仍可提交，但进入“待配置审核人”异常队列，不自动猜测区域经理。
- 主管可看下级事项、证据和日报并审核；间接领导只有已授权的只读视图。
- `sfglzy` 的平台管理员权限不等于任何业务任职；测试时可另配多个岗位，并通过当前任职切换验证各自上下级任务。

## 7. 实施顺序与验收门禁

1. 模板与每日实例：发布 V2 店长工作包，停用旧店长日清分配，自动生成当天实例且无重复。
2. 提醒与企微：四阶段提醒幂等入队，企业微信深链直达对应事项。
3. 证据链：相机、文件上传、水印、元数据、病毒扫描、服务端提交校验全部通过。
4. 日报投影：审核通过后自动形成日报事实，证据可追溯，其他工作可手填。
5. 智能分析：只总结已落库事实，保留来源，失败不阻塞日报人工提交。
6. 闭环核查：桌面端和移动端完成正常、逾期、退回补交、缺证据、重复提醒、一人多岗和无主管负向测试。

任一步未通过自动化测试和浏览器验收，不进入下一岗位模板复制；其他岗位只能基于本模板机制配置，不复制店长的具体业务内容。

### 7.1 生产调度开关

- 生产环境只能启用一个事项调度入口。首选统一自动化进程：`AUTOMATION_WORKER_ENABLED=true`，并在 `AUTOMATION_WORKER_TENANT_IDS` 中明确租户。
- 若独立启用 `WORK_EXPECTATION_SLA_SCHEDULER_ENABLED=true`，统一自动化进程不得再处理同一租户；虽然提醒有幂等键，仍禁止双调度造成无效扫描和竞态。
- 企业微信外部送达仍受独立的企业微信投递开关和凭据控制；站内提醒成功不等同于企微送达成功，运维验收必须分别检查通知记录与投递记录。
- 当前仓库的生产引导脚本保持关闭自动化开关；正式启用属于部署变更，必须在目标租户完成模板、主管链、企微凭据和回滚检查后单独批准。

## 8. 变更控制

以下变化必须先更新本冻结：增加/删除检查点、调整时间窗或提醒、引入定位/人脸识别、自动创建整改任务、绕过主管审核、扩大文件格式或大小、启用区域经理、将集团总经理与门店店长合并。
